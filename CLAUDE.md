# CLAUDE.md

Monorepo of an identity provider for the Symfony ecosystem. The design lives in the parent repository: `../docs/11-architecture.md` and `../docs/decisions/`. Those decisions are settled; do not reopen them here.

Work is organised in spikes, each one a question with a success criterion, a failure criterion and an end date, written before it starts. The spike in progress owns what gets built: **nothing outside its scope is built, even when it is easy** (decision 0005). The spike READMEs live in `../spikes/`.

## Packages

| Directory | Package | Namespace | Rule |
|---|---|---|---|
| `src/core` | `beffroi/core` | `Beffroi\Core` | Identity core. Pure PHP. Knows no protocol, no HTTP, no container, no Doctrine. |
| `src/oidc` | `beffroi/oidc` | `Beffroi\Oidc` | OAuth 2.0 / OpenID Connect. Pure PHP. Depends on the core only. |
| `src/symfony` | `beffroi/symfony-bundle` | `Beffroi\Bundle` | Symfony integration. The only place where `Request`, DI and Doctrine appear. |
| `src/xml-security` | `beffroi/xml-security` | `Beffroi\Xml` | XML security: `Core`, a safe DOM (hardened loading, one ID space, canonicalization, serialization); `Dsig`, XML Signature; `Enc`, XML Encryption. Pure PHP, depends on nothing here. |
| `src/saml2-model` | `beffroi/saml2-model` | `Beffroi\Saml2\Model` | The SAML 2.0 messages, assertions and metadata, read strictly, validated and written. No HTTP. Depends on `beffroi/xml-security` only. |
| `src/saml2-bindings` | `beffroi/saml2-bindings` | `Beffroi\Saml2\Bindings` | HTTP-Redirect and HTTP-POST: a query string or a form decoded into the document the model reads, the detached signature verified over the octets the sender signed, a message the model writes turned into a URL or a form. Strings and arrays, no HTTP object. Depends on `beffroi/saml2-model` and `beffroi/xml-security` only. |
| `apps/op` | `beffroi/op` | `App` | Standalone application, FrankenPHP. |
| `apps/website` | `beffroi/website` | `App` | The website of beffroi.tech, on Scalingo. An application of its own: nothing of the identity provider requires it, it requires nothing of it, and it is installed and analysed apart from `apps/op`. |

Inside each pure-PHP package of the identity provider: `Domain`, `Port`, `Application`, `Bridge`. Deptrac enforces both the package graph and the layers (`.ci-tools/deptrac.yaml`), the namespaces of the SAML packages included. Each SAML package carries its specification in `spec/`, the law of its code: the code conforms to it, or the document changes first, in its own commit, with its reason. Every package is mirrored read only into a repository of its own (`.gitsplit.yml`); the work happens here. The website is not mirrored: nobody installs it.

## Working on an issue

One issue, one worktree, one branch, one pull request here, one documentation pull request in the parent repository.

- **Worktree.** `git worktree add` under the session scratchpad, branched from `origin/HEAD`, the maintenance branch the clone points at. The shared checkout at `~/Projects/idp/code` belongs to whoever is using it; never move its branch.
- **Branch.** `feat|fix|test|refactor|ci|chore/<issue>-<slug>`, for instance `feat/162-dpop`.
- **Commit.** `type(scope): what it does, lowercase, no final period (issue #N)`. Scopes: `core`, `oidc`, `symfony`, `xml-security`, `saml2-model`, `saml2-bindings`, `app`, `conformance`, `website`. English, here as everywhere in the code.
- **Before the pull request.** `castor prepare-pr`, then `castor phpunit`, `castor phpstan`, `castor deptrac`, and `castor app-phpunit` when the change touches the application or anything its kernel wires. Infection runs on the diff in CI; run `castor infect --diff` yourself when the change is a rule rather than plumbing.
- **Opening it.** `gh pr create --head <branch>` always: another session can move the current branch of a shared checkout under you.
- **Status.** A long-running issue keeps **one** status comment, edited in place. Never a new comment per update.
- **The documentation pull request** goes to `beffroi-php/design`, branch `docs/<issue>-<slug>`: the journal row of the spike, and whatever page the change makes false (`docs/11-architecture.md` first). Its rules are that repository's `CLAUDE.md`; the one that bites most often is that a page states the present state and never how it got there.
- **What the spike cannot absorb** becomes an issue tied to the spike that makes it necessary, naming the pattern to reproduce. It is not built ahead, and it is not left unwritten.

## Closing a spike

**The conclusion is written on the end date, whatever the outcome, and a spike is not closed until every line below is done.** A green run that nobody wrote down is not a result, and a spike that stops without a conclusion is the failure mode decision 0005 exists to prevent.

1. **Re-run the judge, on the maintenance branch, after the merge.** The certification plans in `--strict` (`gh workflow run conformance.yml --ref <branch>`), plus whatever else judges this spike. Nothing runs them for you at the merge: the workflow is asked for by hand and by a weekly schedule, so the run that closes a spike is a run somebody started and read.
2. **Name every red.** A module that stays red is listed in the `known` list of `CONFORMANCE_PLANS` with its reason and the issue that closes it, once the gap is written down, never to quiet a surprise. The run then fails the day it passes, so the line is deleted rather than carried.
3. **Write the conclusion** in the spike README, in the parent repository, in its established shape: **the answer, yes or no**, then one line per success criterion with the number or the run that proves it, then what the spike cost and taught, then what it leaves open, each open item naming its issue.
4. **Leave nothing unattached.** Everything the spike found and did not build is an issue on the spike that will need it, and the ones left over from the previous spike have moved on or been closed.
5. **Update the pages the spike made false**, at least `../docs/07-certifications.md` (the state of each plan), `../docs/08-roadmap.md` and `../docs/10-questions-ouvertes.md`, from which an answered question leaves for `../docs/decisions/`.
6. **Close the epic** with the documentation pull request that carries the conclusion.

The journal is written as the spike runs, one row per working day, `Fait` and `Appris`, not reconstructed at the end. A row already written is never rewritten to look better.

`--service` a service obtaining a token for itself for a resource it named, a gateway exchanging it to act on its behalf, and the resource server of the demonstration naming the subject and the actor and refusing a token addressed elsewhere. `--forge` the forge of clients of the demonstration, where a client is composed option by option out of what the provider announces and registered on the spot (RFC 7591): every preset of that page built, signed in with, replayed from what the provider recorded and deleted again (RFC 7592), from a client that puts the whole authorization request in the URL of a browser to one that pushes it signed, reads a signed response, holds a bound token and opens an encrypted ID token, plus one composition the walk writes itself that no preset holds; the page of each built client says which item of `../docs/specs/symfony-oauth-oidc-status.md` that composition would have hit, and the walk asserts that too. It asks the tenant for the mode decision 0009 calls controlled by initial token for the length of its run, with a credential the console issued, and gives it back. A preset the provider refuses for a reason that is written down carries its issue in `DEMO_FORGE_PRESETS` and the walk asserts the refusal, as the `known` list of the conformance plans does. `--flows` opens the pages of the demonstration where every flow this provider serves is drawn, four actors, a marker between them and the payload of every hop as it really was, the set of pictures coming from the wired grants and from nothing kept beside them; then it plays the device grant and the backchannel flow hop by hop from a page, the polling included, the code typed and the request allowed in a browser of the walk, and `--forge` replays the sign-in of each client it built from what the provider recorded while it happened. `--ciba`, `--assertion`, `--rar` and `--native` play the flows no browser of the demonstration reaches, their clients being the programs of `tests/demo/`. `--push` stands a push service of the lab up (`tests/demo/push-service.php`, HTTPS on a certificate the walk issues and makes the `worker` container trust) and a browser of the lab (`tests/demo/push-browser.php`, which draws the key pair of a subscription and holds the private half), then has the notification of a backchannel request signed, encrypted, carried and opened, with nothing in it naming the request; ## Conventions

- PHP 8.4 is the floor in `composer.json`; 8.5 is what actually runs, on the machine as in CI, where the 8.4 job is commented out. Symfony 8.2 (dev branches until release). `declare(strict_types=1)`, `final` by default, public readonly properties on value objects, no getters/setters on entities.
- No variadic parameter (`Type ...$values`): a function that takes several values takes a typed list (`@param list<Type> $values`). Spreading a list into a call (`...$arguments`) is not concerned.
- Test names cite the specification section they verify: `#[Test] public function itRejectsPlainPkceMethod(): void` with `RFC 7636 §4.3` in the docblock. The form of a test is fixed, see "Tests" below.
- Every secret string comes from `random_bytes()`, every secret comparison goes through `hash_equals()`, no boolean coming from a third party is ever cast.
- Security rules of decision 0006 are code, not configuration: no `insecure_*` option, no global compatibility switch.
- Functional tests boot `tests/symfony/Functional/AppKernel.php` with `APP_DEBUG=0`; bundles are listed in `tests/symfony/config/bundles.php`.
- Controllers are `final readonly`, one action per class, `#[Route]` on `__invoke()`. Route names carry their plane: `beffroi_interaction_*` (browser: authorize, login, consent, logout) or `beffroi_protocol_*` (server to server: discovery, jwks, token, userinfo, introspect, revoke). `BEFFROI_PLANE` restricts a process to one plane. The pages where the demonstration draws the flows (`app_demonstration_*`, `apps/op/src/Demonstration/`) are the application's and live under the same rule: routed in development and in the application's own suite, wired in neither environment else, and holding the payload of every hop a flow exchanged, tokens and all. The endpoints of the FIDO conformance tools (`beffroi_fido_conformance_*`, `src/symfony/src/Fido/Conformance/`) belong to no plane and to no environment but dev: their route file is imported by the application only, never by the bundle's `config/routes.php`, and the application never imports Symfony's `routing.controllers` resource, which would route every `#[Route]` service unprefixed.
- No write is synchronous unless the protocol needs its result in the same request; every exception is listed in `apps/op/config/packages/messenger.yaml` with its reason. Messages implement `Beffroi\Bundle\Message\{Command,Query,Event,SyncMessage}`; handlers live in `MessageHandler/` and call the use cases of the core. The core dispatches PSR-14 events only.
- An event is built where it is raised: its constructor takes exactly what it carries, and nothing on it reads a domain object to fill it (no `static of()` on a class of `Domain/Event`, in either package). What it carries is what survives the queue it is written to, so it holds a domain object only when that object leaves the process whole (`CredentialEnrolled` holds its credential) and the facts by identifier otherwise (`TokensIssued` names its client: a client carries the reader of its `jwks_uri`, which no broker can be sent). `EventsLeaveTheProcessTest` writes every event of the module to a queue and reads it back, and fails on an event it does not cover. A reading several events need is a named mapper beside the objects it reads (`RevokedTokenHashes`), never a method of the event.
- Every user-facing string is translated (XLIFF intl-icu, domain `beffroi`, `en` and `fr`). The locale of an interaction comes from `ui_locales`, then `Accept-Language`, never from the URL.
- Every session and event carries a `RequestContext` (IP, user agent, later GeoIP and device); enrichment is always asynchronous.
- A test never sleeps. Time is moved with the mocked clock (`BrowserTestCase::aSecondLater()`), which the Symfony `clock` service reads globally and which survives a kernel reboot.

## SOLID

A rule of every PR, not a theme of a review. Each form below names the class to imitate.

- **One responsibility per class.** A block written a second time becomes a use case or a value object, never a third copy: opening a session is `SessionOpener` (the counterpart of `SessionTerminator`), revoking a set of refresh tokens is `RefreshTokenRevocation`, reading a scope list is `Scope::parseList()`, what a session had proven at a grant is `AuthenticationSnapshot`, a consent extends itself (`Consent::extendedWith()`). A use case orchestrates; a rule of an entity lives on the entity. A command that reads is not the command that writes (`beffroi:user:show`, `beffroi:user:profile`).
- **Open by addition.** A new credential kind, grant, hasher, token format, client authentication method, PKCE method, signature algorithm or confirmation is a class that implements the interface of its capability (`CredentialEnrolmentInterface`, `GrantInterface`, `AlgorithmPasswordHasherInterface`, `AccessTokenIssuerInterface` per format, `ClientAuthenticationMethodInterface`, `CodeChallengeMethodInterface`, `SignatureAlgorithmInterface`, `ConfirmationInterface`), tagged or listed in the wiring; never a `match` on kinds, an enum of kinds, a registry by class or a class name read. A kind names itself (`Credential::kind()`) and declares what it can do by an interface (`RevocableCredentialInterface`, `ExternallyIdentifiedCredentialInterface`). An enum is for a closed set the protocol fixes **that a value carries and nothing acts on** (`Prompt`, `Display`, `LogoutChannel`, the reason enumerations of both packages); what behaves is a class per case, whatever the specification does about the set, because the behaviour is what every caller wants of it (a PKCE method computes a challenge and compares it, `CodeChallengeMethodInterface`). A set the wiring decides may not be an enum at all.
- **One source of truth.** What the provider announces is derived from what is wired: the discovery document reads the tagged grants, the wired client authentication methods and the wired algorithms, never an enumeration kept in parallel. Two places that must agree are one place.
- **Substitutable.** What an implementation throws is in the contract of its interface (`@throws`, and a precondition such as `supports()` is on the contract that has it, not on the port a use case sees). A subtype narrows a return type, never widens a precondition. Intersection types (`Credential&RevocableCredentialInterface`) over downcasts.
- **Small interfaces, per capability.** A port has one to five methods, a caller sees what it calls and nothing else (`PasswordHasherInterface` for the use cases, `AlgorithmPasswordHasherInterface` for the registry; the `CanRevoke*` companions of the access token repository). When two callers use disjoint halves of a port, split it.
- **No Doctrine embeddable, and the document belongs to the object.** A value object a column holds whole goes in **one** column, and **what that column holds is written by the object, in the package that owns it**, as one named pair: `toDocument()` and `fromDocument()` on the object (`RequestContext`, `Address`, `TenantLook`), or, when reading it back names a class the wiring holds, a named mapper of `Application` that takes the wiring as an argument (`StoredPasswordHash`, `StoredClientSecret`, `StoredCodeChallenge`). A member is read through `Domain\Encoding\Document`, which refuses what it is not instead of coercing it, and the constructor of the object refuses the rest, so a row edited by hand fails at load and a round trip costs no connection. The DBAL type of the bundle keeps the Doctrine half and nothing else: the name the mapping uses, the declaration of the column, the JSON, and the `ValueNotConvertible` a refusal of the package becomes (`AuthenticationProofsType`, `ClaimsRequestType`, `RequestContextType`). An embeddable fixes the type of each of its fields once for the whole model, so the same field cannot carry the type of each table that holds the object, and `attribute-override` does not help: the XML driver applies it before `inlineEmbeddable()`, so it throws. An embeddable cannot be null either, which is what makes a mapping contort itself. **One embeddable is left in the mapping**, `AuthorizationRequest`, and it stays for a reason no rule overrides: its first field is a `Client`, an entity the mapping does not carry and a listener writes after the load, so no type can hand the object back whole, and the seventeen others are value objects with DBAL types of their own, two of which are handed a registry at boot. A ninth type would absorb eight. Its two hints are sealed columns, which a field of an embeddable may carry only while **one** entity embeds it, the family of a sealed column being its own table: `Interaction` alone embeds it. What holds it to that is the suite and not a comment, because the mapping that would be wrong is the one that does not change: `OneEmbeddableRemainsTest` refuses a second embeddable and holds the exemption to each of those reasons, figure by figure, and `Sealed` with `ClassifiedSchema` refuse a field that seals under a table that is not its own.
- **Depend inwards.** `Domain` depends on PHP, PSR, the core and the bricks of `../docs/09-briques.md` (webauthn-lib in the core's model is the one named exception); `Application` on `Domain` and `Port`; `Bridge` implements. Deptrac (`.ci-tools/deptrac.yaml`) enforces it; a new dependency is a layer added there with its reason, never a rule relaxed.

## Tests

Same form as the maintainer's other projects. Every test, unit or functional, present or to come, follows it.

- One test verifies one behaviour. Several assertions are fine when they describe the single outcome (the fields of the object created, the claims of the token issued, the event recorded); a test never verifies an acceptance and a refusal, two calls with different inputs, or two rules of the specification. Split it, or use a data provider.
- Every test is laid out in three blocks introduced by `// Given`, `// When` and `// Then`, in that order, separated by a blank line. `// Given` is omitted when `setUp()` and the fixtures already provide everything; `// When / Then` joins the last two when the call is the assertion (a one-line `assertSame` on a constructor or a pure function).
- Expected exception: `// Given`, then `// Then` with `expectException()` and `expectExceptionMessageIs()` (or `expectExceptionMessageIsOrContains()` for a fragment; `expectExceptionMessage()` is deprecated in PHPUnit 13), then `// When` with the call as the last statement. When the test needs a property of the exception the message does not carry (`redirectable`, `reason`, `interactionId`, `getPrevious()`), catch it: `// When` on the `try`, `static::fail()` right after the call, `// Then` inside the `catch`. The state left after a failure is another test, whose `// When` swallows the exception with an empty `catch`. A class that repeats the same failing call may wrap it in a private helper whose name says so (`failToAuthenticate()`), returning the exception or nothing, called under `// When`.
- Same behaviour on several inputs: `#[DataProvider('provideXxx')]` and a `public static function provideXxx(): iterable` with named cases (`yield 'empty' => ['']`), declared right after the test that uses it.
- Doubles: the fixtures (`tests/*/Fixture`) and the in-memory adapters of the `Bridge` first; `createStub()` for a dependency without expectations, `createMock()` only to verify a call.
